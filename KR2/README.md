# Anti-Plagiarism HSE 🔍📝

## Технологии
- ASP.NET Core для создания веб-API
- Entity Framework Core для работы с базами данных
- PostgreSQL для хранения данных
- Docker для контейнеризации и оркестрации микросервисов
- Swagger для документирования API

## Архитектура системы

Система состоит из трех микросервисов:

1. **API Gateway** - отвечает за маршрутизацию запросов к соответствующим микросервисам
   - Компонент `PlagiarismController` нужен для API запросов к сервису.
   - Использует YARP (Yet Another Reverse Proxy) для проксирования запросов. В `appsettings.json` указаны адреса на микросервисы и когда контроллер этого сервиса делает запрос, например вида `/api/files/{**catch-all}` он автоматически перенаправляется на File Storing Service.
2. **File Storing Service** - отвечает за хранение и управление файлами
   - Компонент `FilesController` нужен для API запросов к сервису.
   - Компонент `FileHashService` вычисляет хеш файлов для быстрого сравнения и выявления дубликатов. Не дает пользователю загрузить такой же файл повторно. Проект реализовн "в розовом мире", где коллизий между хешами не бывает :D.
   - Компонент `FileStorageService` отвечает за непосредственное сохранение и "выдачу" пользователю файлов.
3. **File Analysis Service** - отвечает за анализ текстовых файлов и обнаружение плагиата
   - Компонент `AnalysisController` нужен для API запросов к сервису.
   - Компонент `FileStoringServiceClient` делает запросы к **File Storing Service** для получения непосредственно самих данных для анализа.
   - Компонент `TextAnalysisService` проводит сравнительный анализ файла со всеми доступными в базе по принципу косинусного сходства. Каждый текст представляется в виде "вектора" слов, где каждый компонент вектора - это частота встречаемости того или иного слова. Тогда схожесть просто считается как cos(θ) = (A·B) / (||A|| × ||B||). Конечно, такой подход не учитывает порядок слов и прочее, но думаю такой подход сравнения лучше, чем ничего или просто посимвольное сравнение :D. При этом плагиатом считается совпадение более чем на 50% (когда значение схожести больше 0.5).
   - Компонент `WordCloudService` отвечает за создание облака слов путем отправки запроса на https://quickchart.io/wordcloud, а также за сохранение полученных результатов. Для получения более красивых результатов из переданного текста убираются предлоги (просто все слова, длина которых меньше 3).

## Пользовательские сценарии

### Сценарий "Загрузка файла"
1. Пользователь загружает файл через API Gateway.
2. API Gateway перенаправляет запрос в File Storing Service.
3. File Storing Service вычисляет хеш файла и проверяет, существует ли такой файл (предполагается, что коллизий нет).
4. Если файл новый, он сохраняется в хранилище, иначе, пользователю выскакивает ошибка, о том, что файл с таким содержимым уже существует.
5. File Storing Service возвращает ID файла, если он был сохранен.

Идея использования здесь такая: студент загружает свою работу, получает id файла, проводит анализ файла и сообщает id файла преподавателю. Преподаватель может проверить результат с помощью id и специального endpoint. Если студент попытается загрузить файл, который уже есть в системе, то не получит id и система не сохранит дубликат. Таким образом, студент не узнает id оригинального файла, не сможет назвать этот id преподавателю, и, соотвественно, не сможет выдать этот файл за свой.

### Сценарий "Анализ файла"
1. Пользователь отправляет запрос на анализ файла по ID.
2. API Gateway перенаправляет запрос в File Analysis Service.
3. Проверяется, если анализ уже был сделан, то данные возвращаются из базы данных, иначе дальше идет пункт 4.
4. File Analysis Service запрашивает содержимое файла у File Storing Service.
5. File Analysis Service анализирует файл:
   - Подсчитывает количество абзацев, слов и символов
   - Проверяет схожесть с другими файлами
   - Генерирует облако слов (с помощью запроса)
6. Результаты анализа сохраняются в базе данных и возвращаются пользователю.

### Сценарий "Получение файла"
1. Пользователь отправляет запрос на получение файла по ID.
2. API Gateway перенаправляет запрос в File Storing Service.
3. File Storing Service возвращает содержимое файла (если он существует, иначе - ошибка).

### Сценарий "Получение результатов анализа"
1. Пользователь отправляет запрос на получение анализа файла по ID.
2. API Gateway перенаправляет запрос в File Analysis Service.
3. File Analysis Service возвращает результаты уже проведенного анализа (если он существует, иначе - ошибка).

### Сценарий "Получение облака слов"
1. Пользователь отправляет запрос на получение облака слов по ID файла.
2. API Gateway перенаправляет запрос в File Analysis Service.
3. File Analysis Service возвращает изображение облака слов (если оно существует, иначе - ошибка).

## API Endpoints

В рамках КР сделан доступ ко всем сервисам через порты 8000-8002, хотя, конечно, подразумевается, что пользователь будет работать только с API Gateway. Я просто написал документцию Swagger с xml комментариями, поэтому почитать про API можно просто добавив `/swagger` к адресу нужного сервиса (например, http://localhost:8000/swagger). Поскольку в Swagger все описано, не буду здесь много и подробно описывать, просто опишу зачем какой endpoint нужен.

### API Gateway (порт 8000)
- `POST /api/Plagiarism/upload` - Загрузка файла
- `POST /api/Plagiarism/analyze/{fileId}` - Анализ файла
- `GET /api/Plagiarism/file/{fileId}` - Получение файла
- `GET /api/Plagiarism/analysis/{fileId}` - Получение результатов анализа
- `GET /api/Plagiarism/word-cloud/{fileId}` - Получение облака слов

### File Storing Service (порт 8001)
- `POST /api/Files/upload` - Загрузка файла
- `GET /api/Files/{id}` - Получение файла
- `GET /api/Files/{id}/metadata` - Получение метаданных файла

### File Analysis Service (порт 8002)
- `POST /api/Analysis/{fileId}` - Анализ файла
- `GET /api/Analysis/{fileId}` - Получение результатов анализа
- `GET /api/Analysis/word-cloud/{fileId}` - Получение облака слов

## Запуск проекта
1. Скомпилировать проект
   ```
   docker-compose build
   ```
2. Запустить проект
   ```
   docker-compose up -d
   ```
3. Сервисы будут доступны по следующим адресам:
   - API Gateway: http://localhost:8000
   - File Storing Service: http://localhost:8001
   - File Analysis Service: http://localhost:8002
